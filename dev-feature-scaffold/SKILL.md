# dev-feature-scaffold — 需求澄清式功能开发

用户给一句话需求（如"我要开发一个客户管理功能"），**不要直接写代码**。
先经过三阶段：澄清提问 → 蓝图确认 → 生成验证。

## 阶段 1：澄清提问（用 AskUserQuestion，选择题形式，一次 3-4 个问题）

按以下固定维度依次问，不要跳步，不要连环追问超过 3 轮：

### 第 1 轮：业务本质
- **管理对象**：这个功能管的核心实体是什么？（如：客户/订单/设备）
- **核心操作**：除了增删改查，还需要哪些？（导入导出/审批流/批量操作/分配归属，多选）
- **数据关系**：实体之间有无主从关系？（如客户下有多个联系人、订单下有多个明细）

### 第 2 轮：页面形态（布局从"大宗商品行业布局库"中选）

**先按第 1 轮答案推断功能类型，从布局库挑最相关的 3-4 个作为选项（推荐的排第一，标注"推荐"），不要把布局库全量甩给用户。**

#### 大宗商品行业布局库

| 编号 | 布局 | 结构 | 典型场景 |
|---|---|---|---|
| L1 | 标准列表 | 上：搜索区 + 下：数据表格 | 客户管理、供应商管理、订单查询等主数据管理，最通用 |
| L2 | 主从树表 | 左：品类/机构树（可折叠）+ 右：列表 | 品类→品名→规格层级（如煤炭/化工品类）、集团→子公司机构树、仓库分组 |
| L3 | 交易工作台 | 左：合约/品类树 + 中：盘口/挂牌报价列表 + 右：下单或快捷操作面板 | 挂牌摘牌、竞价撮合、报价管理 |
| L4 | 行情看板 | 多品种报价卡片网格（价格、涨跌、迷你走势）+ 顶部市场切换 | 首页行情、多品种价格总览、指数监控 |
| L5 | 汇总+标签页详情 | 上：状态汇总卡片（金额/数量/进度）+ 中：标签页分组内容 + 右：操作与进度时间线 | 订单/合同/履约单详情（基本信息、明细、资金流水、物流、附件分标签） |
| L6 | 流程审批 | 左：待办列表 + 右：单据详情 + 流程时间线（节点/审批人/意见） | 入市审核、授信审批、出金审批 |
| L7 | 仓储物流跟踪 | 上：状态看板（入库/在库/出库/在途数量）+ 下：单据表格，或按状态分列看板 | 库存管理、出入库、物流跟踪、仓单管理 |
| L8 | 上下表单 | 上：基础信息 + 下：明细行编辑表格（可增删行） | 合同录入（抬头+计价明细）、采购单、结算单 |
| L9 | 手风琴/分步表单 | 字段分组折叠或分步引导 | 开户、入市申请等多分组长表单 |
| L10 | 竞价交易室 | 顶部：竞价信息 + 阶段进度条 + 实时倒计时（走动）；中部：竞价时空图（横轴时间分段、纵轴价格档位，热力格显示各时段出价人数与出价量）；右侧：实时出价流水（滚动）+ 出价操作面板；开场有竞价开始大字动画界面；结束后展示成交结果 | 竞价/竞拍/拍卖交易：正向竞价（卖单多买家抬价）、反向竞价（采购多供应商降价）、挂牌竞价详情 |

**L10 竞价交易室要素（领导明确要求过，缺一不可）**：
1. **阶段进度走动**：阶段划分（待开始 → 自由竞价期 → 最后倒计时期 → 成交）以进度条/时间轴展示，当前阶段高亮，随时间自动推进
2. **倒计时不间断走动**：秒级刷新，最后 60 秒变红放大并脉冲闪烁
3. **竞价时空图**：按时间分段（如每 30 秒一格）展示该时段：出价人数（格上方计数）、各价格档位的出价量（热力格深浅/柱高），可回看整场竞价节奏
4. **开场界面**：竞价开始时有仪式感的开场动画（场次信息 + 起拍价 + 开始倒计时 3-2-1），投屏效果佳
5. **成交结果页**：成交价、成交量、成交对手、竞价曲线回顾

#### 门户/大厅类布局库（大宗商品行业门户）

功能涉及"门户、首页、大厅、大屏、资讯、商城"时，从下面的 P 系列布局选：

| 编号 | 布局 | 结构 | 典型场景 |
|---|---|---|---|
| P1 | 多楼层门户 | 顶部导航 + 顶部行情滚动条（各品种最新价跑马灯）+ 楼层纵向排布（每层：楼层标题 + 左右分栏内容），楼层可拖拽排序 | 交易所/平台门户首页：行情快讯层、热门挂牌层、新闻资讯层、供需信息层、成交动态层、合作机构层 |
| P2 | 行情大厅 | 顶部市场/品种切换 + 全屏密集报价墙（表格化：品种/最新价/涨跌/涨跌幅/成交量，红涨绿跌高亮），支持全屏投放、轮播翻页 | 行情大厅页面、营业厅/交易大厅投屏、监控大屏 |
| P3 | 供需撮合大厅 | 左右双栏或 Tab 切换的"供应/需求"挂牌列表（品种、数量、价格、交货地、有效期），支持快速摘牌联系 | 供需信息发布、资源大厅、产能对接 |
| P4 | 资讯门户 | 左：资讯列表（分类 Tab）+ 右：热点排行/公告速览，详情为图文页 | 行业资讯、市场分析、政策公告频道 |
| P5 | 商城式门户 | 顶部搜索 + 品类导航 + 商品卡片网格（价格、起订量、交货地、供应商），进详情下单 | 现货商城、集采专区、标品超市 |

**P 系列提问差异**：门户类不问"表单复杂度"，改问：
- **楼层/版块内容**：需要哪些楼层（多选，按 P1 楼层清单给选项）
- **行情数据源**：接入真实行情（指定接口）还是先 mock
- **投屏需求**（P2 适用）：是否需要大屏全屏模式、轮播翻页

#### 大屏/地图/报表类布局库（大宗商品行业）

功能涉及"大屏、监控、地图、看板、统计、报表、分析"时，从下面的 D/M/R 系列布局选：

| 编号 | 布局 | 结构 | 典型场景 |
|---|---|---|---|
| D1 | 指挥驾驶舱 | 深色背景 + 顶部标题栏（含时间/轮播控制）+ 核心指标卡横排 + 中间主视觉（图表/地图）+ 左右两侧图表列 | 经营驾驶舱、交易监控大屏、领导汇报投屏 |
| D2 | 实时监控大屏 | 全屏密集数据区：滚动表格（最新成交/预警）、实时曲线、报警提示浮层，数据自动刷新 | 实时成交监控、风险预警大屏、系统运行监控 |
| M1 | 地图主视觉 | 中央中国地图（热力/气泡标注各区域交易量、库存、价格），两侧或下方为区域明细/排行 | 全国交易分布、区域价格地图、产能分布图 |
| M2 | 地图+列表联动 | 左：地图（点击省份/仓库定位）+ 右：该区域仓库/库点列表与库存明细 | 交割库分布、仓库网络查询、在途物流地图 |
| M3 | 轨迹地图 | 地图为主体，标注物流轨迹（起点→终点线路动画）、车辆/船位置，侧边为运单列表 | 物流跟踪、在途监控、发运计划 |
| R1 | 多维报表 | 顶部查询条件区 + 报表表格（合并表头/小计合计行）+ 导出，支持行转列或透视 | 日报/月报、交易结算报表、对账单 |
| R2 | 统计看板 | 顶部时间/维度切换 + 指标卡行 + 多图表网格（趋势线、柱状、饼图、排行榜），可下钻 | 交易分析、客户分析、品类分析、运营看板 |
| R3 | 自助仪表盘 | 左：报表/组件目录树 + 右：自由拖拽画布（组件可拖放、保存布局），多用户自定义 | 自助报表平台、可配置数据看板 |

**地图类合规提示**：涉及中国地图必须使用合规地图数据源（腾讯地图/高德/天地图等），省界与藏南等区域绘制必须完整准确，禁止使用无审图号的境外地图库或自绘边界。

**D/M/R 系列提问差异**：不问"表单复杂度"，改问：
- **数据刷新**：静态查询 / 手动刷新 / 自动轮询（问轮询间隔）
- **投屏适配**（D 系列适用）：目标分辨率（1920×1080 / 2K / 4K 拼接屏）、是否需要全屏模式
- **图表维度**：需要按什么维度切（时间/品类/机构/区域，多选）
- **导出需求**（R 系列适用）：Excel / PDF / 不需要

#### 提问方式

- **布局方案**：结合映射给出 3-4 个选项，每个附一句适用场景；推荐项排第一并在描述中说明推断理由（"您做的是品类相关的管理功能，通常有层级…"）
- **列表能力**：分页/搜索/筛选/排序/行内编辑/导入导出/批量操作（多选）
- **表单复杂度**：简单弹窗 / 抽屉 / 独立页面 / 分步表单

**提问原则**：每个选项必须带"适用场景"描述，让用户看选项就能决策；用户选"其他"自由输入时，理解后纳入蓝图，不再重复问；用户否掉推荐布局时，直接按用户选择走，不解释争论。

### 第 3 轮（仅在需要时）：接口与集成
- 需要对接哪些已有服务或外部接口（结合大宗平台常见集成：银行资金/短信/证书签章/物流/开票/企查查/供应链金融）
- 权限控制粒度（页面级/按钮级/数据级，如按机构隔离数据）

## 阶段 2：蓝图确认

生成一份简明蓝图（用 markdown 表格 + 简单结构示意），包含：

1. **页面结构**：标注所选布局编号（L1-L9 / P1-P5 / D1-D2 / M1-M3 / R1-R3），布局示意（文字版线框，标注各区域内容）
2. **字段表**：字段名 / 类型 / 是否必填 / 是否列表展示 / 是否搜索条件
3. **接口清单**：方法 / 路径 / 用途（对齐用户后端习惯：Java，REST 风格）
4. **技术约定**：前端 Vue（组件库按用户项目现状）+ 后端 Java + mock 数据

明确问一句："蓝图确认吗？确认后我开始生成。" 用户确认后才进阶段 3。
用户提出修改，改完蓝图再确认一次。

## 阶段 3：生成与验证

按蓝图生成，顺序固定：

1. 后端：Entity / Mapper(或 Repository) / Service / Controller / DTO，附建表 SQL
2. 前端：API 封装 → 页面组件（含列表、搜索、表单弹窗/抽屉）→ 路由注册 → 菜单项
3. Mock 数据（便于前端先行联调）
4. **验证闭环**：前端 build 通过、后端 compile 通过，报告结果
5. 输出交付说明：改了哪些文件、入口路由是什么、如何启动验证

## 硬性规则

- 阶段 1 不可跳过——哪怕需求看起来很明确，至少问一轮布局和操作范围
- 阶段 2 用户未确认，不得进入阶段 3
- 阶段 3 结束必须报告 build/compile 结果，未通过要修复到通过
- 文件写入用户当前项目时遵循项目已有目录结构与命名规范，先读项目再写
