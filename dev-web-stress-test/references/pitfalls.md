# 避坑清单（全部实战踩过，动手前通读）

## 协议与测量

1. **推送受众别假设广播**——先做四组对照实验（protocol-discovery §4）。实战：方案按"广播扇出"设计，实测只有出价方收到回执，M5a 指标整条作废重拆。
2. **延迟匹配条件要校验语义**——"轮询值 ≥ 出价价"在出价价=旧底价时提前命中，P50 假快；以"T0 前基线变化"为准。
3. **鉴权字段在登录响应里找**，不是探活接口（FIRMID 教训）；WS 登录帧需要 token+FIRMID，缺一个就退化成游客帧（表现为"明明传了 token 却收到 F409 应答"）。
4. **出价/下单定价跟随实时底价**（爬梯语义），固定价会被拒；先试写一笔再跑批量。
5. **时钟**：延迟测量两端同机最稳；跨机 NTP。响应体里的服务端时间戳可做对时参考。
6. **测试场次会售罄**（剩余量 0/BIDSTATE 结束态）——执行前先探测场次状态，全量扫描找 BIDSTATE=1 的场次；写操作仅限测试场次 + 显式确认参数。

## JMeter / 工具

7. 集合点类名是 `SyncTimer` 不是 SynchronizingTimer（写错整计划解析崩）。
8. ConstantTimer 挂控制器 = 每采样器延迟一次；"每轮一次"要挂首个采样器子树。
9. jtl 追加写——重跑先删旧文件。
10. SPA 路由 404+正常内容：断言勾"忽略状态码"（`Assertion.assume_success=true`）+ 内容断言。
11. 静态资源名随部署变——从 HTML 动态提取，不写死。
12. argparse：子命令通过 `parents=[...]` 继承参数组后**不能再重复定义同名参数**（--duration 三处重复的教训：启动即崩，还容易误判成环境问题）。

## Windows 批处理（启动器）

13. 中文 .bat 用 **GBK + CRLF** 保存（UTF-8 会被 cmd 按 GBK 解析、行在汉字处断裂），`chcp 936`。
14. `echo >>>` 的尖括号会被当重定向符（"此时不应有 >"）；`echo` 文本避开 `<` `>` `|`。
15. `if not /i` 语序非法，正确是 `if /i not`；多行 `( ... )` 块易碎，优先单行 IF + GOTO。
16. `set /p` 在**重定向输入**下第二个读取拿不到值（测试怪癖，键盘交互正常）——批处理菜单验证走命令行参数入口，别用管道喂输入。

## Python / 环境

17. Windows 上 Python 看不到 Git Bash 的 `/tmp`（MSYS 映射到 AppData\Local\Temp）——跨工具传文件用工作目录绝对路径。
18. 控制台中文乱码：GBK 控制台里 Python UTF-8 输出会花——启动器里 `set PYTHONIOENCODING=gbk`，或脚本 `sys.stdout.reconfigure`。
19. 进程监控别只看 python 数量（系统常驻 python 多）；用 jmeter/java 进程 + 运行目录 jtl 增长判断。
20. node 脚本的 `require` 解析相对**脚本所在目录**——生成器搬家后要重装依赖或设 NODE_PATH。

## 执行与结论

21. **双口径分开统计**：无缓存最坏模型看静态容量，缓存模型做指标判定；混在一起结论必歪。
22. **环境劣化时段的数据别当能力结论**——空载基线抬升（所有接口统一 +500ms 且与并发无关）就健康窗口复测，判定用复测值，劣化单独归因。
23. **中止阶段照实标注**："部分数据（中止）"，jtl 里捞出来补录，别当 0 也别当全量。
24. **P95/P99 判定，不用平均值**——平均 1s、P95 3.5s 的长尾必须暴露。
25. 熔断护栏：滚动错误率（近 200 次）超阈值自动停压；洪峰场景单独跑（集合点全量汇合会卡住其他组）。
26. **报告数字全部来自结果文件**，未测写"未测"，不适用写"不适用"（如架构无广播则"扇出延迟"标注不适用而非硬测）。
27. 压测前书面授权；避开真实高峰与闭市窗口（交易类系统 8:30–17:30）；长稳勿跨闭市。
28. 每轮保持场次参数/并发/节奏一致才有可比性；结果目录命名带时间戳 + 口径。

## 容量探顶与负载模型

29. **轮询模型吞吐 = 线程 ÷ 轮询周期**——"CPU 上不来"先算这笔账（20 标的 × 1s 档 ≈ 50 QPS，服务端并发需求 ≈ 4 个），别急着怀疑系统。
30. **RT 突增而 CPU 不动 = 串行瓶颈**（连接池 maxCon / per-user 锁排队），不是"没压到"——这种发现比 CPU 打满更有价值。
31. **列表页重查询是压测主力**（单发 600ms~1.2s 级），只压详情页快轮询会系统性低估负载。
32. **每协议必带封装注入字段**（浏览器 postAPI 自动注入的 COMPID 之类，手工构造报文漏了报 001000/GB2001）；**指令报文内嵌 JSON 必须紧凑无空格**（自研解析器，`json.dumps` 默认带空格会报 Missing value）。
33. **匿名报错 ≠ 参数错**——先补 `Authorization: Bearer` 再下结论（登录态接口匿名 001000 被误记"参数需联调"的教训）。
34. **分片必须并行起压**：合并时校验各片时间窗重叠，顺序跑的数据不能当 N 片并发口径；单机 JMeter ~4k QPS 上限，压测机用 typeperf 记 CPU 自证。
35. **探顶档增益 <5% = 吞吐平台期（拐点候选）**；能力表述用"拐点并发 × 该点 TPS + 三曲线"，不用"最高压到 X"。

## 数据面与会话

36. **标的/场次清单跨天过期**——每天开工先重扫；占位符/TODO 标的 = 压异常分支不是真实负载；自建场次时长必须覆盖压测窗口；清单只剩几行时当事故处理。
37. **token 类会话 ~1h 过期**：长跑配会话守护（定期验活自动重登）；会话文件被 JMeter 占用时写 JSONL 跳过 CSV 并告警；链路校验组第一个采样器就打登录态接口，不带病开压。
