# 信息化 / 系统集成 标书行业片段

> 用法：并入通用骨架。本片段同时适用于政企信息化、软件平台、智能化弱电、数据中台类项目。
> 系统集成标的技术分占比最高，且"演示"往往决定成败——投标全链路包里的演示物料就是为这一环准备的。

## 1. 评标权重典型分布

| 评分块 | 常见区间 | 本行业特点 |
|---|---|---|
| 商务分 | 15–25 | 资质等级（CMMI/ITSS/等保）、同类业绩 |
| 技术分 | **45–60** | 方案、架构、演示、项目经理能力 |
| 价格分 | 25–40 | 价格权重最低的行业之一，低价不占优 |

## 2. 必答资格件（缺一件即废标）

| 材料 | 常见出具方 | 易错点 |
|---|---|---|
| 营业执照（含软件开发/系统集成经营范围） | 工商 | 纯贸易公司投集成项目 |
| 软件企业认定 / CMMI / ITSS 证书 | 认证机构 | 等级不够仍去投（资格门槛硬性） |
| 信息安全等级保护相关资质 | 公安/测评机构 | 政务项目常要求等保测评能力 |
| 项目经理证书（PMP/信息系统项目管理师） | PMI/人社 | 证书持有人未在投标单位缴纳社保 |
| 同类项目业绩（合同+验收报告） | 自备 | 只有合同没有验收报告 |
| 原厂授权（软硬件品牌） | 品牌方 | 项目授权 vs 渠道授权混淆 |

## 3. 技术偏离高发区（★/▲ 高频落点）

1. **参数逐条响应**：技术规格书动辄数百条，★/▲ 条款必须逐条正面响应，"满足/响应"四字不算，要给出实现方式。
2. **架构与技术栈**：要求国产化（信创）时，CPU/OS/数据库/中间件须逐项列明品牌型号。
3. **性能指标**：并发数、响应时间、可用性（99.9%），须给出压测方案与依据。
4. **安全保障**：等保级别、数据加密、审计日志，常为★条款。
5. **实施与培训**：实施周期、驻场人数、培训课时、验收标准。
6. **售后承诺**：7×24 响应、2 小时到场、备件库位置。

## 4. 加分项抓手

- **可运行 Demo / 原型**（本行业转化率最高的加分手段，见 `bundle-gov-delivery`）
- 架构图与部署拓扑（清晰度直接影响技术分档位）
- 项目经理与核心团队履历（同行业项目经验）
- 类似规模案例的验收报告与用户评价
- 信创适配清单与互认证书

## 5. 报价注意

- 硬件、软件、实施、运维分开报价（很多项目要求分项报价，混报会被要求澄清）。
- 三年运维费是否含在总价内——漏算即亏。
- 付款节点与验收挂钩，垫资压力要算进报价。

## 6. 本行业高频废标原因

【致命】★参数未逐条正面响应（只写"完全满足"）
【致命】资质等级不满足资格门槛
【致命】项目经理社保不在投标单位
【高风险】信创要求未逐项列明品牌型号
【高风险】只提供合同、无验收报告
【高风险】投标文件未按格式分册（商务/技术/报价）
