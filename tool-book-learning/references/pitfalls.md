## 一、切章与页码

- **扫描件书签是页级噪音**：`get_toc()` 可能返回几百条 lv=1 的纯页码条目。
  `init_book.py` 已做两层防护（只取最浅层级 + 剔除页码型标题 + `--max-chapters` 截断），
  实测 490 页的《深入分析Java Web技术内幕》从 470 章降到 6 章。
  **但仍要看一眼输出章数**——十几章以下说明书签层级不对，得渲染目录页人工重填。
- **L1 粒度常常太粗**：658 页的《凤凰架构》L1 只切出 10 章，"架构师的视角"一家占 181 页。
  解法：`make_map.py --dump-toc` 导出完整书签树，按 L2/L3 手写 map.json 重切成 18 章。
- **合集型书（多篇长文/多册合订）TOC 完全不可信**：《工业AI学习笔记》书签 1010 条，
  lv1 里混装「篇/章/节」。解法：`make_map.py --titles-file`，
  用「文章目录页列出的篇标题」在正文里定位**首次出现页**做章边界，再逐章核对首页首行。
  该书篇内层级还极不统一：篇1 用「第一章~第七章」，篇6/9/13 用「第X部」，
  篇2/4/5/10/11/15/16 用「一、二、三」，篇3 用「第X部分」——所以**别用「第N章」正则去猜**。
- **目录页不计入任何章节正文**：目录本身的 PDF 页不��第 1 章，
  `pdf_start` 要顶到**正文真正首页**（"第N章 标题"那一页），否则笔记会混入目录碎片。
- **按章切页避免模糊匹配**："第1章"式前缀匹配会误命中"第1章附录"，用显式页范围。

## 二、page_offset（最容易错、且不报错）

**符号约定：`书页 = PDF 0-based索引 + page_offset`**（是加不是减，通常为负）。
例：正文第一页在 PDFIDX=21 且印着"书页 1" → `page_offset = -20`。

- **填反了不会报错**，只会让页码标签整体错位几十页。实测曾把 PDFIDX=22 标成"书页 42"，
  肉眼很难立刻发现。校准后务必核对 OCR 文本头部页码与页面实际印刷页码是否一致。
- **offset 必须用两个以上锚点交叉验证，因为扉页让它不均匀**：
  目录标"第2章在书页46"不等于 `pdf = 46 + offset` 就是章首页——**每个"部分"之间常插一张无页码扉页**。
  实测《人工智能（第2版）》：第1章首页 PDFIDX=28、第2章首页 PDFIDX=72，两处 offset 都是 −26，
  中间恰好多出一张"第二部分 基础知识"扉页 PDFIDX=71。
  **做法**：先用一个 offset 粗算全部章节，再逐章（或抽查）渲染首页验证；
  改完**必须检查相邻章范围是否重叠**。用 `make_map.py --render-homes` 一步到位。

## 三、笔记内容

- **不要写 `- **误区**：` 前缀**：模板已有 ⚠ 图标（`.panel.pitfalls .lst li::marker`），
  写了会渲染成「⚠ - 误区：…」重复。`- **深入**：` 要保留，模板没给深入部分图标。
  `audit_notes.py` 会把这条判为 ERROR。
  （实测《失控》24 章共 70 处，审计一次全抓出来。）
- **每个代码块首行必须有 `// caption:`**（xml/text 用 `<!-- caption: -->`）。
  缺 caption 是最高频错误：`audit_notes.py` 判 ERROR。实测 18 章里查出 3 章共 21 个块缺。
- **答案混在题干里**：`build_site.py` 按 `**Q**：` / `**A**：` 配对。
  若写成"Q：…… 答案……"（答案没单独起行、没标 `**A**：`），站点上点"查看答案"展开是空盒子。
  实测发生过 22 条。`verify_site.py` 现在会全量展开后逐题查答案文本，能兜住。
- **统计 H1/H2/H3 前必须先按 ``` 切块、跳过代码块内部**——否则代码里的 `#` 注释会被当成标题，
  报出 `H1=51` 这种荒谬假警报。（`audit_notes.py` 已内置这个处理。）
- **OCR 会认错形近符号**：`$`→`S`（`Yuyi$Inner` 被读成 `YuyiSInner`）、`0/O`、`1/l`、
  `（）` 常变全半角混用。写笔记时按技术常识还原，别把 OCR 错别字当知识点写进卡片。
- **图页不是"没字"，是"字碎"**：实测插图页 OCR 能抓到 500+ 字，只是标签顺序被打乱。
  所以 `need_vision` 判定不能只看字数，碎片化（平均行长）判据必须有。

## 四、build_site 解析器

- **正文里的引用块（`> `）不能当章末概括**：`parse_note` 只认 H1 之后的第一个引用块作为 subtitle。
  否则正文中间的引用块会覆盖概括，站点上表现为**"第N章标题下显示第N+1章的内容"**。
  改这块时务必用**两章以上**的笔记验证 H2 与 ch-sub 是否一一对应。
- **`split_blocks` 的行推进必须可证**：段落分支遇到 `> ` 开头会 `break` 但**不推进 `i`**，
  而 `> ` 又在段落循环的排除条件里——于是 `para` 为空、什么都不产出、`i` 不变，**形成死循环**
  （表现为编译站点一直挂住、超时被误报成 SIGTERM）。
  现已加 `> ` 显式分支 + `elif i < n: i += 1` 安全网。
  **教训**：手写 while 循环解析器时每个分支都要保证 `i` 前进；
  调试"莫名超时/SIGTERM"先怀疑死循环，别急着怀疑正则——**所有正则实测都是毫秒级**。
- **统计必须递归且覆盖全部固定小节**：`###` 可以出现在卡片里，也可以出现在固定小节里。
  只扫一层 + 只扫 `special["code"]` 会漏算。
  实测《凤凰架构》统计条报 536 卡片 / 115 代码块，DOM 实际 **537 / 144** —— 站点自己骗自己。
  现在用 `audit_notes.py --check-site` 强制核对统计口径 == 渲染口径。
- **模块级常量快照陷阱**：`PANEL_TITLES = panel_titles()` 写在模块层，
  求值时机早于 `build()` 里设置 profile，导致 `--profile prose` 生效了、面板标题仍是「代码要点」，
  每章渲染一个错名空面板。**凡是依赖运行时可变量（profile/配置）的表，一律惰性求值。**
- **`## ` 只能有两种**：节标题 + 5 个固定小节。出现第三类会让解析错位。

## 五、站点验证

- **选择器必须以 `assets/site_template.html` 为准**，别凭印象写：
  搜索框 `#q` + `#qcount`（**不是** `#search`）；自测答案点 `.ans-btn`（点 `.qa` 本身**无效**）；
  打卡点 `.done-btn`（点 `.card` 无效）；窄屏汉堡 `#menuBtn`。
  写错的表现是 Playwright 30s 超时，**很容易误判成"站点坏了"**。
- **搜索命中的隐藏范围必须覆盖全**：`verify_site.py` 会查
  `.card / .sec / .chapter / .panel / .qa / .code-block / .tbl-wrap` 以及 `tr`。
  漏任何一个都会让"命中数 vs 可见卡片数"对不上。
- **搜索零命中时 qcount 显示"无匹配"不含数字**：解析时要当 0 处理，
  当成 -1 会误报 FAIL。
- **窄屏点击被fixed 元素遮挡时 Playwright 会反复重试超时**：测试脚本用
  `eval_on_selector(e=>e.click())` 绕过 actionability 检查。
- **slug 不能只留 ASCII**：localStorage 打卡键由书名派生，全中文书名会被清洗成 `book`，
  多本书的进度会互相覆盖。

## 六、并行与工程

- **子代理并发上限 3**：曾 4 并发被风控拒。
- **子代理可能只回 agent ID 而不落盘**：必须用 `os.listdir` 核验真实产物，缺则重派；
  重派提示词里明确写"这次是重派，务必真实 Write 并回报字节数"。
- **Playwright 只装在 「已装 Playwright 的解释器」**；build/audit 纯标准库脚本用托管 python 即可。
- **中文路径**：bash 里对中文文件名 mv/rm 可能报错但实际生效，核验用 Python `os.listdir()`。
- **⚠ 重编译前先看 notes 是否覆盖全部章节**：
  若某本书的 `index.html` 含**手工增强内容**（自制 CSS、图表、17 章而 notes 只有 2 章），
  直接跑 `build_site.py` 会把它覆盖成占位版，内容当场蒸发。
  判据：`len(notes/ch*.md) < len(map.json 的 chapters)` → 先备份、确认可弃，再重编译。
  实测事故：《人工智能（第2版）》966KB 完整版被覆盖成 153KB 的 2 章版。
- **单文件 HTML 全压成一行**：`grep` 会匹配并吐出整行（几十万字符），
  查子串要用 Python 计数 + 上下文切片，不要用 grep。

## 七、环境

- `ocr_extract.py` OCR 后端首选 `rapidocr-onnxruntime`（已装）；
  本机 `pytesseract` 缺 tesseract.exe 引擎、不能用。扫描件 `--dpi 200`。
- 修改重要文件一律 **Write 落成 .py 再执行**，别用 heredoc 内联
  （反斜杠/反引号会被静默吞掉，且行为不稳定），改完必须复核实际内容。
- 全角中文引号 `"` `"` 直接放进 Python 字符串会截断语句，
  报错信息还会误导成"语法错误"。字符串里需要强调时用 `『』` 或 `「」`。
