# 修复分档细则与专项模式

阶段 2 修复战役的详细手册。SKILL.md 给流程，本文给"具体怎么修"。所有模式都经 2026-11-08 战役实证。

## 一、悬空数字修复分档（最常见、最易出错）

为知/语雀导出丢失正文数字，修复分三档，判定标准必须写进代理 prompt：

### 【可推断修复档】代码/命令中机械可推断的值
判断标准：**任何有编程/运维常识的人都能唯一确定**。
- `for (int i = ; ...)` → `for (int i = 0; ...)`（循环起始几乎必然是 0）
- `跳转到第一行 ：*` → `：1`（语义明确）
- `sort -k -g -r` → `sort -k2 -g -r`（按 `jmap -histo` 输出列语义可推断列号）
- `pluginDefines.size() >)` → `> 0`（集合非空判断）
- 公认协议/常识值：三次握手、IPv4 32 位、snowflake 41/10/12 位、`sync_binlog 0/1` 双值列举
- 修复处加注释：代码用 `// 注：原导出数字缺失，此处为修复值`，shell 用 `# 注：...`

### 【改写保通顺档】统计数据/百分比/引用类数字
判断标准：这是**数据主张**，猜错比缺失更糟。
- `"只有 % 的软件项目是成功，其他 % …"` → `"多数软件项目并不成功，其他相当比例的项目不是失败，就是存在严重问题"`
- `"B 提升了 %，B 提升了 %"`（连版本字母都丢）→ 整句改写为定性结论（`"两个方案都不同程度提升了转化率…选择了提升更明显的一个"`）
- JVM 参数 `"经验值在~左右"` → `"经验值视堆大小而定"`
- 改写后**不留横幅**（读者不会误以为有数据主张）；若原文已有的 ⚠️"数字缺失"横幅因修复而不再成立 → 移除

### 【如实标注档】无法修复
- 代码中关键阈值不可推断且失去教学价值 → 删代码块，保留文字说明"此处代码示例因导出缺失已移除"
- 截断文档（自称 100 问实存 46 问）→ 文首加注"原文件号称100问，导出仅存46问"，文末加"> 注：导出截断，第47问及以后未导出"，**绝不补写**
- 年份错字有明确依据的可修（CHAOS Report 2010），无依据的不猜

**反例警示**：绝对禁止把 `"只有 %"` 补成 `"只有 30%"` ——哪怕概率上像。数据类数字宁可改写定性，不可编造。

## 二、存根/空壳处理流程

1. **逐个甄别**（不能批量 rm）：`<2KB` 文件分三类——纯存根（仅标题/bookmark/一行）、完整短笔记（有一句以上实质内容）、索引页（链接合集）。
2. 纯存根 → 归档区；短笔记 → 保留原样；索引页 → 保留（有导航价值）。
3. **空目录**：`find <dir> -mindepth 1 -type d -empty` 清点后归档区记录、原目录移除。
4. **同名共存**（顶层 stub + 子目录真文）：stub 归档后顶层不留死链来源。
5. 整系列全空壳 → 系列目录整体归档，上级 README 注明"××系列 N 篇未导出，仅存标题，归档见 _备份元数据"。
6. **README 必建**：如实列出现存篇数、完整系列、断档系列（逐篇标注"缺失，未导出"）。

## 三、平台标记转换对照表

| 来源标记 | 转换目标 |
|---|---|
| `<callout>`（飞书/为知提示块） | `>` 引用块 |
| `<bookmark>` | markdown 链接 |
| `<sub-page-list>` | `子页面：xxx` 列表 |
| `<cite>` | 链接 |
| `<whiteboard>`/PDF附件 | 如实注记"未随文档导出" |
| `:::info` / `:::warning`（语雀） | `>` 引用块 |
| `<title>文件名</title>`（首行） | 直接删行（与文件名逐字一致时信息无损；转 H1 会造成双 H1） |
| `<font>` 包裹（语雀噪音） | 剥壳保文字（代码块内不动） |
| 图片 AI 长 alt（最长 325 字） | 精简为 ≤50 字短 alt，图片本身全保留 |
| NBSP（U+00A0，`\xa0`）散布全文 | 全文件替换为普通空格。代码块里的 NBSP 会让复制粘贴的代码无法编译；实战中 86 个文件中招（为知两库重灾区）。**注意：含 NBSP 的行会让"裸字符串替换/正则"静默失配**（`Integer a = ;` 三次替换失败才靠 repr 发现），先清 NBSP 再做其他文本替换 |

**转换安全性断言（必做）**：逐文件对比转换前后 CJK 字符数，`转换后 ≥ 转换前 - 已知删除量`，发现"无法解释的文字丢失"立即回退。这是防止转换吞文的核心手段。

## 四、AI 注水模板判定（删/留标准）

症状：同一句式大量重复（实战：90/136 篇含"硬件层面/操作系统层面"，单篇最多 17 处，且常有机理错误，如"硬件层面比较唯一性"——真实机制是唯一性约束）。

判定流程：先抽 10 篇精读确定模板形态（行尾追加句/配对标签小节/独立大节），然后逐段：
- **删**：该段删掉后文章论证链完整无缺口；内容泛泛而谈与主题无强关联；机理是错的
- **留**：标签下是真主题内容（如"硬件层面"下讲 MESI 缓存一致性协议——硬件即主题本体）；含具体参数/机制讲解
- **宁留勿错删**：拿不准的保留。大规模自动清理时写 audit.jsonl 审计日志，对"含领域信号的删例"逐一回查（实战回救了染色指针、Serial GC 对比等真实要点）

## 五、结构错位修复

- **H1 课号不符**：以**文件名为准**（文件名保留原编号，正文 H1 是被啃的），`# 第01讲` → `# 第09讲`
- **题不对文**（文件叫 SELECT 正文是 INSERT）：正文实为 INSERT 执行器 → 文件改名 `01-INSERT更新.md` 顶替语义空缺，README/总纲同步
- **编号冲突**（双 01/双 02）：精读判关系——两代重写 → 旧代归档；互补（不同案例/主题）→ 低编号者 `git mv` 顺延为 03/04，查总纲里本就写好的规范编号做佐证
- **状态失真**（"🔄 待完成"实已写完）：抽 3 篇确认 → 批量改"✅ 已完成"；清单漏列的新增篇目一并补全并记版本条目
- **总纲/README 对齐**：已移除章节标"❌ 已清理（低质量草稿）"，未完成标"未完成"，存在的标"✅"

## 六、密码文件处理预案

1. 归档原稿到 `_备份元数据/_<date>修复归档/<库>/_修复前原稿/`
2. 归档区 README 醒目警示："**含脱敏前密码原值，仅供本机密码轮换参考，用后即删**"
3. 原文件内容替换为脱敏说明（保留结构信息如主机/IP/系统名，密码值清零为 `<已脱敏-原值见密码管理器>`），注明备份位置与"尽快轮换"清单
4. 纯密码清单且无其他价值 → 整文件替换为说明段
5. 技术库外发现的密码痕迹（如 `工作/客户跟踪/`）：报告并建议，征得同意再处理（可能含客户语境需要用户判断）

## 七、修复 Agent Prompt 模板骨架

```
你是文章修复工程师。工作目录：<目录>
⚠️该目录被gitignore（或：是git跟踪的成品目录，用git mv，改完不commit）

背景：<审查实锤的问题清单，带文件名和证据引文>

任务：
1. <按问题逐条列任务，每条写明处理分档>
2. 删除/大改前先归档到 <归档区路径>（保持相对结构）
3. <README/总纲对齐任务>

铁律：
1. 绝不编造内容或数字（数据类数字改定性表述；缺失篇目不补写）
2. 可推断的机械值补值+注释；统计值改写；不可推断如实标注
3. gitignore目录删除先mv归档；git跟踪用git mv
4. 链接检查按"目录/子路径"全串匹配，裸文件名grep会误报

自检：<本任务的grep清单 + 抽N篇通读 + 围栏平衡>
报告（≤500字）：各项统计 + 典型前后对照2-3例 + 无法修复清单
```

## 八、终验 grep 清单（scripts/verify_kb.py 的实现依据）

**缩进围栏残骸**（2026-11-08 终验新发现，脚本已覆盖）：导出会把闭合围栏搞成"26 空格缩进 + \`\`\`"（实例：为知·技术专栏/第20课）。宽松奇偶校验（strip 后计数）会报"平衡"，但严格 CommonMark 渲染下缩进>3空格的围栏不算闭合，代码块会一路吞掉后面的中文段落和标题。修复 = 缩进归零。校验脚本按列 0 计数才抓得住这类残骸。

```bash
# 密码残留（工作区，排除归档区）
grep -rln "Root@\|VNC密码\|密码：[A-Za-z0-9]" <库>/ --include="*.md" | grep -v "_备份元数据"
# 存根残留
find <库>/ -name "*.md" -size -100c
# 空目录
find <库>/ -mindepth 1 -type d -empty
# XML/语雀标记残留
grep -rln "<callout>\|<sub-page-list>\|^:::" <库>/ --include="*.md"
# 导出噪音
grep -rln "复制代码" <库>/ --include="*.md"
```

疑似悬空数字（**人工复核项**，误报率高：`% N` 取模、`like '%abc'` 是合法语法）：`" %的"`、`" % 的"`、`）%`、`>){`、`= ;`。代码被啃模式只匹配运算符后接右括号（`[><=!]=?\s*\)\{`），裸的 `){` 是合法方法签名（`void stop(){`）。

**已知误报源**：教人写文档的文档（含嵌套围栏示例，如 CONTRIBUTING_DOCS.md）会让朴素围栏配对错乱，其 fence 内的 `password: your_password` 教程占位符会被误报——人工确认即可。
