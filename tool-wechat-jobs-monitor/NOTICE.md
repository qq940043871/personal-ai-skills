## 为什么把它限定为个人使用

不是功能不足，而是**它的运行前提天然无法转交给别人**：

| 前提 | 说明 | 为什么不能转交 |
|------|------|----------------|
| 非官方接口 | 采集走微信读书 `weread.qq.com` 的网页接口，非公开授权 API | 接口未对外开放授权，第三方使用不受任何协议保护，且随时可能变更或封禁 |
| 浏览器登录态 | 通过读取本机浏览器 cookie 获得登录凭证 | cookie 属于个人账号凭证，转交等于转交账号权限，既不可行也不应做 |
| 内容边界 | 只采集「本人账号有权阅读」的公众号文章 | 这个边界依赖具体账号，换人即失效；越界即构成对他人内容的未授权获取 |
| 平台协议 | 自动化访问可能与微信读书用户协议冲突 | 协议约束的是账号持有人本人，作者无权代他人承担，也无权代他人授权 |

结论：**它是一个"自己给自己用的脚本"，不是一个产品。** 任何把它包装成可分发包的做法，
都会把上述风险转嫁给不知情的接收方。

请停止使用并删除。若确实需要「公众号 / 政策 / 招投标信息的每日摘要」这类能力，
合规路径是：

1. **站点方提供的公开订阅**：政府门户、公共资源交易中心、招标公告网站的 RSS 或邮件订阅
2. **平台官方接口**：微信公众平台的官方能力、各内容平台开放的 API
3. **自建采集需自行评估**：遵守目标站 `robots.txt`、控制访问频率、只取标题/摘要/链接而不复制全文
