# 选号：为什么这比选技术重要一百倍

## 血泪教训

同一个品牌下，**主号和垂直子号的内容可能完全不同**。拿主号去抓招聘，会得到这样的结果：

- 549 篇历史文章，标题 **0 命中**；
- 正文采样 60 篇，只有 **1 篇**沾边。

你会以为是代码坏了 —— 其实只是**走错了门**。公众号本体（微信）也不给你「按名称反查」
的公开接口，微信读书同样没有，所以选号只能靠人给准输入。

## 真实案例对照

| 公众号 | bookId | 实际内容 |
|---|---|---|
| 郑州本地宝（主号） | `MP_WXS_3222425727` | 办事指南：公积金、社保、消费券、人才公寓 |
| 本地宝郑州招聘（子号） | `MP_WXS_3925849039` | **纯招聘**，日更多条 |

对招聘场景，只有后者可用。前者抓一天也筛不出几条招聘。

## 30 秒验证法（务必先做）

向导（`setup_wizard.py`）默认会帮你验证，但手工验证是：

```bash
python scripts/run_pipeline.py --source weread --limit 20 --dry-run
```

看输出：

1. 第 `[2/5] 过滤` 段里，命中的标题是不是你要的**那个号**的内容；
2. 若想直接看号名，向导验证阶段会打印接口返回的 `mp_name`。

**名字不对、内容不对，先把号换对，再谈其它。**

## 怎么拿到 bookId

三种输入向导都能自动识别：

1. **阅读页链接**（最省事）：浏览器打开该号任一文章 → 复制地址栏
   `https://weread.qq.com/web/mp/reader/...` 整条粘进去；
2. **编码串**：`edd420e224d505f5758535f33393235383439303339901` 这类十六进制；
3. **纯 ID**：`MP_WXS_3925849039`。

原理：微信读书把 bookId 按 ASCII 逐字节转十六进制，拼在固定前缀 `647423d2` 后面。
识别逻辑见 `scripts/wjobs/weread.py` 的 `parse_book_id()`。

## 前置条件清单

- [ ] 浏览器登录过 `https://weread.qq.com`（cookie 有效）
- [ ] 在微信读书里**关注**（加书架）了目标公众号
- [ ] 拿到目标号的 bookId（链接 / 编码串 / 纯 ID 任一）
- [ ] 跑过一次验证，确认拉到的标题是目标号的
