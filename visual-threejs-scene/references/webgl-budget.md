# Web 实时渲染预算表（数字孪生大屏）

> 原则：大屏要的是"一眼真"，不是"建模大赛"。预算超线就减，没有商量的余地。

## 几何

| 级别 | 单模型面数 | 用途 | 导出参数 |
|---|---|---|---|
| hero 主角 | ≤50,000 | 相机默认焦点设备（主角储罐/主厂房） | decimate 0.6~1.0 |
| mid 常规 | ≤20,000 | 中景设备、车辆 | decimate 0.4~0.6 |
| bg 远景 | ≤5,000 | 远景楼群、围墙、重复性构件 | decimate 0.2~0.3，或程序化代替 |
| 整场景 | ≤300,000 | 所有模型合计（程序化几何另计） | — |

- 倒角（BEVEL segments=2）是真实感第一来源，减面先减侧面环数、再砍倒角，**最后才砍 hero 细节**。
- 重复构件（栏杆柱、货架立柱）用 Array modifier，导出时已是合并几何，别手动复制几百个对象。

## 贴图

| 项 | 预算 | 说明 |
|---|---|---|
| 单张贴图最长边 | ≤2048px（hero）、≤1024px（其他） | export_webgl.py `--max-tex` |
| 单张贴图体积 | ≤4MB（validate_glb.py 闸门） | 超了说明没压缩或格式不对 |
| 总贴图 | ≤全部 GLB 体积的 60% | 超了改用材质色 + 法线贴图 |
| 格式 | JPG（颜色）/ PNG（带 alpha） | glTF 导出器自动处理 |

- 程序化贴图（混凝土地面、锈迹）优先：零体积、无缝、随便缩。
- **烘焙优先于实时材质**：复杂着色（AO、脏迹）烘成贴图带走，浏览器只做基础 PBR。

## 体积（GLB 单文件）

| 模式 | 单模型上限 | 场景总上限 | 说明 |
|---|---|---|---|
| 内联（visual-digital-twin 默认） | **1.5MB** | 8MB | base64 后 ×1.37 塞进单文件 HTML |
| 外置服务（模型走 HTTP） | 5MB | 30MB | 加载有进度条依赖，注意首屏 |

- 铁律顺序：先 Draco（省 60~80%）→ 再减面 → 再缩贴图 → 最后才考虑外置。
- `validate_glb.py` 默认按内联预算（2MB，留了点余量）把关。

## 尺度

- 单位：**米**。Blender 场景单位必须是 Metric，导出 glTF 默认 1 unit = 1m。
- `validate_glb.py` 会用 POSITION accessor 的 min/max 报包围盒：储罐应该 30m 级、货车 10m 级。报出 30000m = 建模用了毫米，回去重导。
- glTF 是 Y-up：Blender 的 Z（高度）导出后变成 glTF 的 Y。**不需要手动改**——`export_yup=True`（export_webgl.py 默认）由导出器处理；大屏端（three.js）也默认 Y-up，链路对齐。

## 性能底线（验证时看）

- 首帧渲染 ≤5s（headless verify 里 wait 后必须出画）
- FPS ≥30（观众设备是普通办公本，不是你的 4090）
- 内存峰值 ≤1.5GB（Firefox/Edge 开一下任务管理器确认）

超线了：先砍 bg 级模型 → 再统一降贴图 1024 → 最后考虑拆场景分屏。
